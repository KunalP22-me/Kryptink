6. DATABASE REQUIREMENTS & TTL INDEXES
--------------------------------------------------------------------------------
- Database Name     : kryptink
- Collections       : 
    1. rooms        : Stores 6-character room codes and references to notes
    2. notes        : Stores note titles, rich-text HTML bodies, and room refs
- Background TTL    : Both collections must enforce a MongoDB TTL index on
                      `expiresAt` with `expireAfterSeconds: 0` for 24h expiration.
- Cascading Hooks   : Mongoose `findOneAndDelete` pre-hook must cascade-delete
                      all notes associated with an expiring or deleted room.

7. SECURITY & INTEGRITY SPECIFICATIONS
--------------------------------------------------------------------------------
- Cryptographic CSPRNG:
    * Room codes must be generated using `crypto.randomInt` (kernel entropy).
    * Prevents sequence prediction, brute-forcing, and modulo bias.
- Rate Limiting Policy:
    * Room Creation   : Maximum 3 rooms per minute per IP address.
    * Room Join       : Maximum 5 attempts per minute per IP address.
- Session Security:
    * Cookies must be flagged: `httpOnly: true`, `sameSite: 'strict'`,
      and `secure: true` when running in production (`NODE_ENV=production`).
- XSS & UI Redressing Defense:
    * HTML input must be sanitized via `sanitize-html`.
    * Inline `style` attribute must be completely stripped.
    * Only legitimate Quill CSS classes (`ql-align-*`, `ql-size-*`) are whitelisted.
- Payload Controls:
    * Maximum JSON & URL-encoded request body size limited to 1MB.
    * Base64 image paste blocked in Quill editor to prevent database bloat.
